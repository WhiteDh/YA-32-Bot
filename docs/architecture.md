# Архитектура

## Слои

```
bot/  (aiogram: handlers, keyboards, render, middlewares, ui, notify)
  ↓ вызывает
services/  (сценарии над БД: schedule, homework, users, semester, audit, sync, sources)
  ↓ использует
core/  (чистая логика: недели, звонки, сборка дня, настройки)      db/ (модели, движок)
```

`core` не знает ни про Telegram, ни про БД. `services` не знают про Telegram и HTML. HTML
появляется только в `bot/render` и `bot/screens.py`.

## Как устроен день

```
template_lessons ─┐  (неделя 1/2, день, пара, предмет, тип, преподаватель,
                  │   аудитория, dates — если пара идёт только в эти даты)
overrides ────────┼──► core.timetable.build_day(date, week, …) ──► Day(lessons…)
holidays/semester ┘  (cancel / replace / add на конкретную дату)
week_anchor (kv) ──► номер недели для даты
```

Ничего «сгенерированного на неделю вперёд» в базе нет (старый бот копировал шаблон в
календарь). Поменяли шаблон — изменились все будущие дни; поменяли дату — только она.

## Жизнь апдейта

1. `DbSessionMiddleware` открывает сессию (commit после обработчика, rollback при ошибке).
2. `UserMiddleware` делает upsert пользователя, кладёт `user` и `prefs` (владельцы из `OWNER_IDS`).
3. `NavigationResetMiddleware`: команда или кнопка снизу сбрасывает незаконченный ввод (FSM).
4. `ThrottleMiddleware` отсекает двойное нажатие одной и той же кнопки.
5. Роутеры: `start` → `admin` (фильтр роли) → `homework` → `settings` → `schedule` → `easter`
   → `fallback`. Inline-запросы — отдельный роутер.
6. Обработчик берёт экран из `screens.py` и показывает его через `ui.show` (callback
   редактирует сообщение, сообщение получает новый экран).

## Отправка: Rich Messages с откатом

`render/doc.py` — маленькая модель (`Heading`, `Para`, `Quote`) с двумя сериализаторами:
Rich HTML (`<h1>`, `<p>`, `<blockquote>`) для Bot API 10.1 и классический HTML. `ui.send`
пробует Rich; если Telegram откажет, процесс переключается на классику до перезапуска.
Сообщения с reply-клавиатурой и inline-результаты всегда классические.

## Уведомления

`scheduler` раз в минуту зовёт `Notifier.tick(now)`: для каждого пользователя по его `Prefs`
утренний/вечерний дайджест, дедлайны на завтра, напоминание за N минут до пары. Дедупликация
по `(user, key)` в течение дня. В тихие часы сообщения уходят без звука, а не пропадают.

Изменение расписания на ближайшие 7 дней → `schedule_changed(date)` с задержкой 90 с после
последней правки (админ обычно меняет несколько пар подряд) → одно сообщение группе.

## Синхронизация с КПИ

`sources/kpi.py` читает `api.campus.kpi.ua/schedule/lessons?groupId=…` и `/time/current`, а
`sync.diff` сравнивает результат с шаблоном по ключу `(неделя, день, пара, предмет, тип)`.
Режимы: append (только новое), update (строки `source="kpi"`; ручные `manual` не трогаются),
reload (заменить всё). Каждый apply — одна запись журнала, её можно отменить. Номер недели
выставляется из ответа КПИ. Ежедневная автопроверка присылает админам превью или (если
включено) применяет «Оновити» сама.

## Журнал и undo

`audit.Change` собирает обратные операции (insert → delete, delete → вставить сохранённую
строку, update → вернуть старые значения) и пишет их в `audit_log.payload`. `audit.undo`
применяет их в обратном порядке. Так отменяется что угодно: правка дня, шаблон, синк, ДЗ.

## Что где хранится

| Таблица | Что |
|---|---|
| `users` | id Telegram, роль, `prefs` (JSON), `fun` (пасхалки), blocked |
| `template_lessons` | шаблон недели 1/2, `source` = kpi/manual |
| `overrides` | разовые изменения на дату |
| `subjects` | короткое имя, эмодзи, ссылка, примечание (переживают синк) |
| `homework`, `homework_done` | ДЗ и личные отметки |
| `holidays`, `kv` | каникулы; семестр, якорь недели, состояние синка, автосинк |
| `invites`, `audit_log` | приглашения с ролью; журнал правок |
