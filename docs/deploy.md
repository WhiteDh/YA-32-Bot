# Деплой

## Однократная настройка

**1. Токен.** Используется токен существующего бота расписания (тот же, что был у старой
версии). В @BotFather по желанию `/setinline` — для `@бот` в чатах. Команды и описание бота
настраивать не нужно, их публикует сам бот при старте.

**2. Репозиторий на GitHub** (у друга). Settings → Environments → `prod`:

| Секрет | Значение |
|---|---|
| `SERVER_HOST` | `server.zebaro.dev` |
| `SERVER_USER` | `deploy` (в группе `docker`, владелец всего `/srv`) |
| `SSH_PRIVATE_KEY` | приватный ключ пользователя `deploy` — тот же, что в секретах Neko / Bento |
| `BOT_TOKEN` | токен `@YA_32_bot` (прежний) |
| `OWNER_IDS` | числовые Telegram id владельцев через запятую, без пробелов: `123456789` или `123456789,987654321` |

Переменные (необязательно): `KPI_GROUP_ID` (по умолчанию 3655), `LOG_LEVEL`.

**Свой id** — написать @userinfobot (или @getmyid_bot), он ответит числом `Id: 123456789`.
Это не `@username`. Владельцы из `OWNER_IDS` получают роль 👑 при каждом сообщении боту и не
могут быть понижены из интерфейса. Остальных админов и редакторов ДЗ добавляют уже в боте:
«🛠 Адмінка → 👥 Люди → 🔗 Запрошення».

Пароль базы задавать не нужно: у Postgres нет порта наружу, к нему ходит только бот внутри
сети compose (по умолчанию пароль `ya32`, при желании — переменная `POSTGRES_PASSWORD`).

Образ публикуется в `ghcr.io/<owner>/<repo>`. Если пакет приватный, на сервере нужен
`docker login ghcr.io`. CD логинится сам токеном workflow, но для приватного пакета у этого
токена должен быть доступ к нему.

**3. Сервер — уже готов** (проверено 05.10.2026): Debian 13, Docker 29.3, Compose v5.1,
свободно ~4 ГБ RAM и ~196 ГБ диска; папка `/srv/ya32-bot/backups` создана от `deploy`; имена
`ya32-*` не заняты. Руками на сервере ничего делать не нужно.

## Выкатка

`release` → `scripts/release.py` поднимает версию и ставит тег → `git push origin vX.Y.Z` →

1. CI-гейт (тот же `scripts/gate.py --strict`);
2. сборка образа и пуш `:X.Y.Z` и `:latest` в GHCR;
3. `docker-compose.yml` копируется в `/srv/ya32-bot`;
4. **дамп базы** в `/srv/ya32-bot/backups/pre-X.Y.Z-<время>.sql.gz` (хранятся 10 последних);
5. `docker compose -p ya32 up -d --pull always`. Миграции бот применяет сам при старте.

## Ресурсы

| Контейнер | Лимит | В простое |
|---|---|---|
| `ya32-db` (postgres:17-alpine, урезанный конфиг) | 128 MB | ~25–30 MB |
| `ya32-bot` | 192 MB | ~60–80 MB |

Портов наружу нет: long polling, база видна только внутри сети compose.

## Восстановление из дампа

Только с владельцем:

```bash
cd /srv/ya32-bot
docker compose -p ya32 stop ya32-bot
gunzip -c backups/<файл>.sql.gz | docker exec -i ya32-db psql -U ya32 -d ya32 -v ON_ERROR_STOP=1 \
  -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;' -f -
docker compose -p ya32 start ya32-bot
```
